### 2-5. 学生割引（20%OFF）

**単発（都度払い）のみ適用。回数券には適用されない。**

| コース | 学生料金 |
|--------|---------|
| 40分 | 4,800円 |
| 60分 | 7,200円 |
| 80分 | 9,600円 |

### 2-6. 割引の適用ルール（確定）

| 区分 | 適用対象 | 併用 |
|------|---------|------|
| 初回体験 50%OFF | 初めての方の1回目のみ | 他割引との併用不可 |
| 新規限定3回券 15%OFF | 新規のお客様の回数券購入時 | 他割引との併用不可 |
| 回数券 3/6/9%OFF | 4回券 / 8回券 / 12回券 | 他割引との併用不可 |
| 学生割引 20%OFF | **学生の単発利用のみ** | **回数券には適用しない** |

- 学生の初回利用は「初回体験50%OFF（3,000円〜）」の方が学生料金より安いため、**初回は50%OFF、2回目以降は学生20%OFF** を適用する。
- 上記により、料金ページに「学生 × 回数券」の表は**作らない**。

### 2-7. 検算結果

すべての金額が「基本単価 × 回数 × (1 − 割引率)」で**端数なく一致**することを確認済み。
初回50%OFF・学生20%OFF も同様に割り切れる。
よって定数としてハードコードせず、**基本単価と割引率のみを保持して算出する**方式を採用する（二重管理による不整合を防ぐ）。

```
40分 6,000 × 3 × 0.85 = 15,300  ✓      40分 6,000 × 4 × 0.97 = 23,280  ✓
60分 9,000 × 3 × 0.85 = 22,950  ✓      60分 9,000 × 8 × 0.94 = 67,680  ✓
80分 12,000 × 3 × 0.85 = 30,600 ✓      80分 12,000 × 12 × 0.91 = 131,040 ✓
40分 6,000 × 0.80 = 4,800 ✓（学生・単発のみ）
40分 6,000 × 0.50 = 3,000 ✓（初回体験）
```

## 3. 現状の構成と課題

### 現状（1ページLP）

```
app/page.tsx  ──  Hero → Concerns → Features → Trainer → BodyChange → Area → Price → Contact → Footer
                  （全セクションが縦積み。ヘッダーは #アンカーへのスクロール遷移）
```

### 課題

1. **セクション数がすでに8つ**。ここに「回数券（3コース × 4券種 = 12パターン）」「学生料金」を追加すると料金セクションだけで縦に非常に長くなる。
2. ヘッダーナビが `#anchor` スクロールのため、深い情報への直リンク・共有ができない。
3. ページが1つしかないため **SEO 上の受け皿が「料金」「エリア」等の検索語ごとに用意できない**（現状 sitemap.ts はトップ1件のみ）。
4. 料金情報が `PRICING` 定数にベタ書きで、割引・券種という次元を持てない構造。

### 5-1. `app/lib/types.ts`（追加分）

```ts
export type CourseId = "min40" | "min60" | "min80";

/** 施術コース（時間単位） */
export interface Course {
  id: CourseId;
  minutes: number;        // 40 / 60 / 80
  label: string;          // "40分コース"
  basePrice: number;      // 単発の税込価格
  catchCopy: string;      // カード見出し用の一言
  features: string[];     // 特徴リスト
  isPopular?: boolean;
}

/** 回数券プラン */
export interface TicketPlan {
  id: "new3" | "t4" | "t8" | "t12";
  label: string;          // "新規限定3回券"
  sessions: number;       // 3 / 4 / 8 / 12
  discountRate: number;   // 0.15 / 0.03 / 0.06 / 0.09
  newCustomerOnly: boolean;
  note?: string;
}

/** 表示用に算出された価格 */
export interface PriceTier {
  total: number;          // 券の総額
  perSession: number;     // 1回あたり
  listPrice: number;      // 割引前の総額
  saved: number;          // 割引額
}
```

### 新規のお客様の導線（初回50%OFF と 新規限定3回券の関係）

2つの新規向け割引が併存するため、ページ上で**使い分けを明示**する。

```
  ① まず1回試したい      → 初回体験 50%OFF（40分 3,000円〜）
  ② 続けるつもりで始める  → 新規限定 3回券 15%OFF（40分 15,300円 / 1回 5,100円）
```

- 「①で体験 → 気に入ったら②または回数券へ」というステップを図示し、どちらを選ぶべきか迷わせない。
- 併用は不可である旨を早見表（⑤）で明示。

### モバイル対応方針

- 回数券の3×3表は**横スクロールさせない**。SPでは「コース選択タブ（40/60/80分）」で1コースに絞り、券種カードを縦に並べる。
- タブは `useState` によるクライアント側切替（`"use client"`）。
- 数値は等幅寄りに揃え、「1回あたり」を副次表示にして視線を総額へ誘導。

### デザイン方針

- 既存のトーン（cyan-500系グラデーション、`card-premium`、`heading-jp`、`btn-cyan`）を厳守。
- 新規限定3回券は**オレンジ系アクセント**（現行の初回割引バッジと同系統）で「限定感」を出し、通常回数券のシアンと区別する。
- 学生割引は淡いブロックで区切り、対象者以外のノイズにならないようにする。
- 初回体験50%OFFは**ページ最上部のバナー**に置き、単発カード内のバッジと二重に見せて取りこぼしを防ぐ（現行LPの見せ方を踏襲）。

## 12. 送信経路（EmailJS 直送信 → APIルート）

### 現状

`contact-section.tsx` は `@emailjs/browser` を使って**ブラウザから直接** EmailJS に送信している。
`POST /api/send-email` は経由していないため、ルート側のレート制限・サニタイズ・
許可値チェックは**現在は動作していない**。

運用上は EmailJS で足りているため経路は変更せず、**将来ワンステップで移行できる状態**に整備した。

### 移行手順（コード変更は不要）

1. `.env.local` と本番のホスティング環境に以下を設定する。
   ```
   EMAILJS_SERVICE_ID=...
   EMAILJS_TEMPLATE_ID=...
   EMAILJS_PUBLIC_KEY=...
   EMAILJS_PRIVATE_KEY=...          # EmailJS 管理画面 > Account > General > Private Key
   NEXT_PUBLIC_USE_CONTACT_API=true
   ```
2. 再デプロイして予約フォームから送信テストを行う。

`.env.local` には上記をコメントアウト済みの雛形として記載してある。

### 整備した内容

**構造**

| 追加/変更 | 内容 |
|-----------|------|
| `app/lib/contact.ts`（新規） | ペイロード型・時間帯の選択肢・文字数上限・EmailJS テンプレートパラメータ変換を集約。クライアントとサーバーが共有し、フォーム項目の二重管理をなくした |
| `app/lib/send-contact.ts`（新規） | 送信経路の分岐を1箇所に集約。`NEXT_PUBLIC_USE_CONTACT_API` で切り替わる |
| `contact-section.tsx` | 送信処理を `sendContactRequest()` に委譲。EmailJS への直接依存を排除 |

**修正した不具合（移行していたら顕在化していたもの）**

| # | 内容 | 影響 |
|---|------|------|
| 1 | **EmailJS の失敗を無視して常に 200 を返していた** | 送信に失敗しても「送信完了」と表示され、予約を取りこぼす。失敗時は 502 を返すよう修正 |
| 2 | **EmailJS の Private Key（`accessToken`）を送っていなかった** | EmailJS はサーバーからの呼び出しを既定で拒否する。移行した瞬間に全件失敗していた |
| 3 | **環境変数の存在チェックがなかった** | 未設定のまま切り替えると原因不明の失敗になる。503 と案内文を返すよう修正 |
| 4 | `x-forwarded-for` をヘッダ全体でIP識別していた | `"client, proxy"` 形式のため経路が変わるだけで別枠と見なされ、レート制限を回避できた。先頭IPを使うよう修正 |
| 5 | レート制限ストアの掃除がなかった | `Map` が無制限に増え続ける。期限切れの掃除と件数上限を追加 |
| 6 | **バリデーションエラーでもレート制限を消費していた** | 入力ミスを3回するだけで5分間ブロックされる。確認と消費を分離し、実送信時のみ消費するよう修正 |
| 7 | サーバー側に文字数上限チェックがなかった | API を直接叩けば任意長のデータを送れた。`CONTACT_LIMITS` で検証を追加 |
| 8 | `status: 'PENDING'`（旧バックエンドの名残）を送っていた | EmailJS テンプレートに存在しない変数。削除 |
| 9 | 旧バックエンド向けのコメントアウトコード30行が残存 | サーバーでは動かない `setStatus()` を含む死んだコード。削除 |
| 10 | `console.log` でレスポンス本文を常時出力 | 開発時のみ出力するよう変更 |

**検証済み**（ダミーの環境変数を入れて実際に API を叩いて確認）

- 環境変数未設定 → 503 と案内文
- ハニーポット埋め → 200 を装って破棄
- コース／時間の許可値外、過去日、3ヶ月超、名前50字超、message 1000字超、電話番号不正 → いずれも 400
- 正常リクエストで EmailJS が失敗 → **502**（修正前は 200 を返していた）
- 入力ミスを同一IPから5回 → ブロックされない
- 正常リクエストを同一IPから4回 → 4回目が 429
- `x-forwarded-for` の後段IPを変えても先頭IPで識別され、制限を回避できない

### 残る制約

レート制限はインメモリの `Map` で実装しているため、**単一プロセス内でしか機能しない**。
Vercel などのサーバーレス環境ではインスタンスごとに別ストアになる。
厳密な制限が必要になった時点で Upstash Redis 等の外部ストアへ移すこと（コードにも明記済み）。
