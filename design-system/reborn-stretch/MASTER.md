## 1. パターンとスタイル

| 項目 | 採用 | 内容 |
|------|------|------|
| ランディングパターン | **Trust & Authority + Conversion** | 1. 信頼を語るHero → 2. 証拠（資格・実績・変化）→ 3. サービス概要 → 4. 明確なCTA |
| ビジュアルスタイル | **Soft UI Evolution** | やわらかい影 + 明確なコントラスト。200〜300msのトランジション。focus visible 必須。WCAG AA+ |
| モード | **ライトのみ** | ダークモードは提供しない。`prefers-color-scheme` による切替は実装しない |

**コンバージョンの原則**（本パターンの定義より）:
透明な料金、低摩擦のフォーム、資格・実績の可視化。装飾でなく**根拠**で信頼を作る。

**やらないこと**: 蛍光色、激しいアニメーション、ダークモード。

## 2. カラートークン

正の定義は `app/globals.css` の `:root`。Tailwind のクラスを使う場合も下表の**用途規則**に従う。

```css
:root {
  --background:    #ffffff;
  --foreground:    #0f172a;  /* slate-900 */
  --cyan-primary:  #06b6d4;  /* cyan-500 */
  --cyan-mid:      #0891b2;  /* cyan-600 */
  --cyan-deep:     #0e7490;  /* cyan-700 */
}
```

### 2-1. 用途規則（最重要）

cyan は明度が高く、**文字色に使うと簡単にコントラスト基準を割る**。用途で切り分ける。

| トークン | 値 | 白背景での比 | 使ってよい用途 |
|---|---|---|---|
| `cyan-400` | `#22d3ee` | 1.8 | 濃色背景の上のテキスト／グラデーションの明側のみ |
| `cyan-500` | `#06b6d4` | 2.43 | **面・罫線・アイコン・装飾のみ。文字色にしない** |
| `cyan-600` | `#0891b2` | 3.68 | 24px以上または18.66px以上の太字の見出しのみ |
| `cyan-700` | `#0e7490` | 5.36 | **本文・小さいラベルに使える最も明るい cyan。既定値** |
| `cyan-800` | `#155e75` | 7.27 | 濃い強調、ボタン背景の暗端 |

- **テキストに使う cyan は 700 以上**。`text-cyan-500` は原則としてアイコン専用。
- **アクセントのオレンジは「新規・限定」訴求のみ**（初回50%OFF / 新規限定3回券）。
  通常の情報にオレンジを使わない。文字色は **`orange-700`（#c2410c）以上**、
  帯の背景は **`orange-700 → orange-800`**（白文字で 5.18 以上）。
  `orange-600` を帯の明端に使わないこと（白文字で 3.56 しか出ず AA 未達）。
- グレーの本文は **`slate-500`（4.76）が下限**。`slate-400`（2.56）は白・淡色背景では使用禁止。
  `slate-400` が許されるのは `slate-800` 以上の濃色背景の上だけ。
- 濃色背景（`slate-950` / `cyan-900`）の上の白は **`text-white/50` 以上**（5.27）。

### 2-2. 主要ボタン `.btn-cyan`

```css
background: linear-gradient(135deg, #0e7490 0%, #155e75 100%);  /* 白文字で 5.36〜7.27 */
color: #fff;
```

サイトの主要導線がこの1クラスに集約されている。**明るくしないこと。**
華やかさは `box-shadow: 0 4px 20px rgba(6,182,212,.38)` の cyan グローで担保する。

### 2-3. 状態色

| 用途 | 値 | 白背景での比 |
|---|---|---|
| エラー | `text-red-600` `#dc2626` | 4.83 |
| 成功 | `text-green-700` `#15803d`（`green-600` は 3.30 で不足） | 5.02 → **アイコン＋文言と併用**し、色だけで意味を伝えない |
| 必須バッジ | `bg-red-600` + 白文字 | 4.83（`red-500` は 3.76 で不足） |
| 任意バッジ | `bg-slate-500` + 白文字 | 4.76（`slate-300` は白文字が読めない） |

## 3. タイポグラフィ

| 用途 | フォント |
|---|---|
| 見出し（`.heading-jp`） | Noto Serif JP → Hiragino Mincho ProN → Yu Mincho → Georgia |
| 本文 | Geist Sans → Hiragino Kaku Gothic ProN → Noto Sans JP → Meiryo |
| 数値・英字ラベル | `font-mono`（Geist Mono） |

### 3-1. サイズスケール

**このスケール以外の値を使わない。** 任意値（`text-[9px]` 等）は原則禁止。

| トークン | px | 用途 |
|---|---|---|
| `text-xs` | 12 | **下限**。バッジ、注釈、英字ラベル |
| `text-sm` | 14 | 補助テキスト、カード内の説明 |
| `text-base` | 16 | **本文の既定値**。`Section` の `lead`、各セクションの段落 |
| `text-lg` | 18 | 小見出し、カード見出し |
| `text-2xl` | 24 | セクション内の h3 |
| `text-3xl` / `text-4xl` | 30 / 36 | ページ見出し h1・セクション見出し h2 |
| `text-5xl` 以上 | 48+ | Hero の h1、数値の強調表示 |

- **10px 以下は使用禁止。** 日本語は同じ px でも英字より小さく見える。
- 例外はロゴ内の文字のみ（`header.tsx` / `footer-section.tsx` の丸ロゴ）。
- 主要顧客層は肩こり・腰痛を抱えた層であり、若年向けサイトより**一段大きめ**に倒す。

### 3-2. 行間

| 対象 | 値 |
|---|---|
| 本文（日本語） | `leading-[1.9]` |
| 見出し | `leading-tight` 〜 `leading-snug` |
| 最低ライン | 1.5 を下回らない |

### 3-3. 使い分け

- `.heading-jp` は **h1 / h2 / h3 のみ**。本文や UI ラベルには使わない。
- `.text-gradient` は **1ページに1箇所まで**（Hero のキーコピー）。
  グラデーション文字はコントラスト測定ができないため、必ず十分に大きい太字で使う。
- `.eyebrow` は `font-size: .75rem` / `color: #0e7490` 固定。

## 4. スペーシング

Tailwind の 4px 基準スケールを使い、以下の組み合わせに揃える。

| 用途 | 値 |
|---|---|
| セクション上下（見出しあり） | `py-20 sm:py-24` |
| セクション上下（見出しなし） | `py-14 sm:py-16` |
| 見出しブロックとコンテンツの間 | `mb-14 md:mb-16` |
| カード内パディング | `p-6 md:p-7` |
| カード間のグリッド | `gap-5` |
| 横方向のページ余白 | `px-4 sm:px-6 lg:px-8` |
| コンテンツ最大幅 | `max-w-5xl`（本文）/ `max-w-6xl`（画像併用）/ `max-w-7xl`（ヘッダー） |

これらは `app/components/layout/section.tsx` に実装済み。**新しいセクションは必ず `Section` を経由する。**

## 5. モーション

| 項目 | 規則 |
|---|---|
| 標準時間 | **150〜300ms**。ホバー 200-250ms、スクロール表示 700ms まで |
| イージング | `cubic-bezier(.16,1,.3,1)`（減速）。ホバーの押し戻しは `cubic-bezier(.34,1.56,.64,1)` |
| 1画面あたりの主役アニメ | **1〜2要素まで**。すべてを動かさない |
| アニメーションする property | `opacity` / `transform` のみ。`width` / `height` / `top` は動かさない |
| 常時ループ | `.anim-float` のみ。増やさない |
| **`prefers-reduced-motion`** | **必須**。`globals.css` のメディアクエリで全アニメーションを無効化し、`ScrollReveal` は `matchMedia` を見て初期表示する |

`prefers-reduced-motion` 時に「動かないが見えない」状態を作らないこと。
`opacity: 0` を初期値に持つ実装（`ScrollReveal`）は、必ず JS 側でも分岐させる。

## 6. アクセシビリティ基準（必達）

| # | 基準 | 検証方法 |
|---|---|---|
| 1 | 本文 **4.5:1** / 大きい文字（18.66px太字 or 24px以上） **3:1** | Lighthouse アクセシビリティ監査 |
| 2 | すべての操作要素に **`:focus-visible` のリング** | Tab キーだけで全ページを巡回 |
| 3 | タップ領域 **44×44px 以上**、間隔 8px 以上 | 375px エミュレーションで確認 |
| 4 | フォームは `<label for>` + `aria-invalid` + `role="alert"` | VoiceOver で空欄送信 |
| 5 | 非同期処理の結果は `aria-live` で通知 | 同上 |
| 6 | 見出しは h1→h2→h3 の順。**h1 はページに1つ**（`PageHero`） | 見出しアウトラインを確認 |
| 7 | 意味を**色だけ**で伝えない（アイコン・文言を併用） | 目視 |
| 8 | 画像に意味のある `alt`。装飾画像は `alt=""` | 目視 |
| 9 | `prefers-reduced-motion` を尊重 | OS設定を有効にして全ページ確認 |
| 10 | 横スクロールを発生させない | 375 / 768 / 1024 / 1440px で確認 |

## 7. アイコンとビジュアル

- アイコンは **lucide-react**（`react-icons` は SNS ロゴのみ）。**絵文字をアイコンに使わない。**
- サイズは `w-4 h-4`（インライン）/ `w-5 h-5`（ボタン内）/ `w-7 h-7`（機能アイコン）。
- アイコン単体のボタンには必ず `aria-label` を付ける。
- 写真は **WebP**。PNG は透過が必要な図版のみ。
- `next/image` を必ず使う。`unoptimized` は**禁止**（WebP変換と srcset が無効になる）。
- `priority` は **ファーストビューに入る画像のみ**。1ページ 1〜2枚まで。
- 画像には必ず `width`/`height` または `fill` + `sizes` を指定し、CLS を出さない。

### 7-1. 動画

- **自動再生しない。** ポスター画像＋再生ボタンの**ファサード方式**を必ず使う
  （`app/components/ui/video-player.tsx`）。クリックするまで動画ファイルを取得しないこと。
  これで「通信量を無駄にしない」「LCP を悪化させない」「`prefers-reduced-motion` 下で
  勝手に動かない」の3つを同時に満たす。
- **字幕（WebVTT）は必須。** 音声付きの録画済み動画に字幕を付けることは
  **WCAG 2.1 レベルA（1.2.2）の要件**であり、任意項目にしない。
  `SiteVideo.captionSrc`（`app/lib/types.ts`）を optional にしないこと。
- 外枠に実寸から求めた `aspect-ratio` を当て、再生前後でレイアウトを動かさない。
- 再生ボタンは 44×44px 以上、`aria-label` 付き、`:focus-visible` が効くこと。
- エンコード: H.264 / 720p / 約2Mbps / AAC / **`-movflags +faststart` 必須**
  （無いと全体をダウンロードし終えるまで再生が始まらない）。目安 15MB 以下。
- 同じ動画の `VideoObject` 構造化データは**1ページにだけ**置く（重複扱いを避けるため）。
- 動画ファイルが未納品のあいだは `INTRO_VIDEO`（`app/lib/constants.ts`）を `null` にしておく。
  トップの動画枠は Section ごと描画されない（**写真などの代替物で枠を埋めないこと**。
  埋めると結局トレーナー紹介になり、`/trainer` と文言が重複する）。
- `INTRO_VIDEO_PLACEHOLDER` は**見た目確認用のダミー**。`INTRO_VIDEO` が入れば無視されるが、
  **公開前に `null` へ戻すこと。**

## 8. コンポーネントの使い分け

| 場面 | 使うもの |
|---|---|
| 下層ページの見出し | `layout/page-hero.tsx`（h1 + パンくず） |
| セクション枠 | `layout/section.tsx`。見出し不要なら `subTitle`/`mainTitle` を省略する |
| ページ末尾のCTA | `layout/cta-band.tsx`。**全ページ必須**（回遊率の維持） |
| 共通の見た目 | `globals.css` のユーティリティ（`card-premium` / `btn-cyan` / `heading-jp` / `eyebrow` / `text-gradient` / `shadow-cyan*`） |
| スクロール表示 | `ui/scroll-reveal.tsx` |

- **同じセクションコンポーネントを複数ページに置かない**（文言が重複する）。
  トップは要約版、下層ページは詳細版。
- 定数は `app/lib/constants.ts`、型は `app/lib/types.ts`、価格算出は `app/lib/pricing.ts` に集約する。
- `"use client"` は状態・イベントを持つコンポーネントだけに付ける。

## 9. レスポンシブ

- **モバイルファースト**。ブレークポイントは `sm:`(640) / `md:`(768) / `lg:`(1024) / `xl:`(1280)。
- 検証幅は **375 / 768 / 1024 / 1440px**。
- 表組みは横スクロールさせず、SPではカード縦積みに切り替える（`price/ticket-table.tsx` が実装例）。
- ビューポート高は `vh` でなく **`svh`** を使う（モバイルのアドレスバー伸縮対策）。
- 固定要素の下端は `env(safe-area-inset-bottom)` を考慮する。
- ズームを禁止しない（`user-scalable=no` / `maximum-scale=1` を書かない）。

## 10. 実装前チェックリスト

UIを追加・変更したら、コミット前にすべて確認する。

- [ ] 新しい色・文字サイズを **本書のトークンから選んだ**（任意値を足していない）
- [ ] テキストのコントラストが 4.5:1 以上（cyan は 700 以上、slate は 500 以上）
- [ ] 10px 以下の文字を追加していない
- [ ] 絵文字をアイコンに使っていない（lucide-react を使用）
- [ ] クリック可能な要素に `cursor-pointer` と `:focus-visible` がある
- [ ] タップ領域が 44×44px 以上、間隔 8px 以上
- [ ] ホバー/トランジションが 150〜300ms、`opacity`/`transform` のみ
- [ ] `prefers-reduced-motion` で破綻しない（動かない かつ 見える）
- [ ] 画像は `next/image`、WebP、`unoptimized` なし、`priority` は最小限
- [ ] 動画は自動再生していない／字幕がある／アスペクト比で領域を確保している
- [ ] 見出しレベルが飛んでいない。h1 はページに1つ
- [ ] 375 / 768 / 1024 / 1440px で横スクロールが出ない
- [ ] `npm run build` と `npm run lint` が通る
